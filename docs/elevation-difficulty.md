# 고도 기반 예상 난이도 v1

문서·코드 대조일: 2026-10-27. 최초 외부 자료 검토일: 2026-10-19. 구현 정책 버전: `ascent-density-10-30-v1`.

외부 자료는 최초 검토 당시의 설계 참고 자료이며, 이번 갱신은 현재 계산·저장·표시 코드와의 대조입니다.

## 조사 근거와 자체 결정의 구분

- [UTMB Sports System](https://utmb.world/en/sports-system)의 KM-effort는 `거리(km) + 누적 상승(m)/100`이다. 100m 상승을 1km-effort로 더해 거리와 상승을 함께 고려하는 트레일 경기 분류용 지표다.
- [ITRA Runner FAQ](https://itra.run/FAQ/Runner)도 같은 kilometer-effort 개념을 설명하며, 지형의 기술적 난도는 Endurance Points에 포함하지 않는다고 명시한다.
- [Strava Route Difficulty](https://support.strava.com/en-us/articles/15401688-route-difficulty)는 거리·고도·커뮤니티 완주 시간 등을 종합한다. 공개 문서에는 우리 서비스에 그대로 적용할 상/중/하 경계가 제시되어 있지 않다.

위 자료는 '거리와 상승을 함께 고려한다'는 설계 근거다. 아래 10/30m/km 경계는 UTMB·ITRA·Strava의 공식 난이도 기준이 아니다. 생활권 코스의 오르막 부담을 비교하기 위해 우리가 정한, 아직 사용자 검증 전인 초기 가설이다. KM-effort를 생리적 에너지 소비량·예상 시간·실제 거리로 해석하지 않는다.

## 계산

`상승 밀도(m/km) = 평활화·임계값 처리한 누적 상승(m) / 경로 길이(km)`

| 표시 | 상승 밀도 | 5km 예시 |
| --- | --- | --- |
| 하 | 10m/km 미만 | 누적 상승 50m 미만 |
| 중 | 10m/km 이상, 30m/km 미만 | 50m 이상, 150m 미만 |
| 상 | 30m/km 이상 | 150m 이상 |

KM-effort 증가분을 원래 거리로 나누면 상승 밀도/100이 된다. 10/30 경계는 이 지표상의 추가분 10%/30%와 대응하도록 선택했다. 이는 '실제 운동 강도 10%/30% 증가'라는 뜻이 아니다. UI에서는 이해하기 쉬운 m/km만 설명한다.

거리와 상승은 동일 고도 미리보기 응답에서 가져오며, 화면 반올림 전 값으로 판정한다. 0m 상승은 하, 데이터 미조회·누락·오류는 '—'로 표시하고 하로 추정하지 않는다. 정책은 Kotlin에서 계산해 `difficulty.level`, `ascentMetersPerKm`, `policyVersion`으로 반환한다. 프론트엔드는 표시만 담당한다.

## 저장·목록·상세의 연결

- 고도 API는 `difficulty.level`을 `LOW`/`MEDIUM`/`HIGH`로 반환하며 화면은 하/중/상으로 표시합니다.
- 생성·수정 API의 `elevationProfile`에 난이도와 정책 버전을 함께 전달하면 JSONB로 저장합니다.
- 목록·찜 목록은 저장 프로필의 등급을 `elevationDifficulty`로 요약하며, 상세는 전체 프로필을 반환합니다.
- 프로필이 없으면 null 또는 ‘—’이며, 데이터가 없다고 LOW로 추정하지 않습니다.
- 상세 화면은 저장 프로필을 표시합니다. 기존 데이터가 현재 정책으로 자동 재계산되는 것은 아닙니다.
- 저장 API는 클라이언트가 전달한 고도·등급을 별도로 재검증하지 않습니다. 이를 검증된 실측 등급으로 해석하면 안 됩니다.
- 저장 코스의 `distanceMeters`는 PostGIS 계산값이고 난이도 분모는 고도 프로필의 구면 거리입니다. 같은 거리라고 가정해 클라이언트에서 등급을 재계산하지 않습니다.

구체적 응답 필드·샘플링·자동 조회·재시도·사용량 제한은 [고도 API](api/elevation.md)를 참고합니다.

## 화면 의미

요약 순서: 전체 거리 → 누적 고도 → 최고 고도 → 예상 난이도. 누적 고도는 누적 상승을 뜻하며 '오르막 높이 합계'를 함께 표시한다. 하강 계산은 백엔드 응답에 유지하지만 요약 카드는 제거한다.

난이도 카드에는 '고도 기준'을 병기한다. 고도 기반 비교 지표이므로 평지 42km도 '하'일 수 있으며, 42km가 누구에게나 쉽다는 뜻이 아니다. 긴 코스의 한 구간에 집중된 급경사는 평균에 가려질 수 있다. 노면·계단·기술적 지형·날씨·개인 체력·다리·터널 보정은 포함하지 않는다. 구간별 고도는 그래프에서 확인한다.

## 추후 검증

평지·완만한 언덕·언덕 반복·급경사 집중 코스를 거리대별로 수집하고, 실제 러너의 '고도 때문에 느낀 부담' 평가와 비교한다. DEM·평활화 오차와 임계값 부근의 등급 변동도 확인한다. 10/30 경계 조정 시 정책 버전을 올리고, 실측 검증 전에는 공인 난이도·안전 판단·예상 기록으로 홍보하지 않는다.

## 구현과 검증 기준

현재 정책은 `ElevationDifficulty.kt`의 `ElevationDifficultyPolicy.assess()`에 있습니다.
`ElevationDifficultyTests`는 10m/km·30m/km 경계, 거리·상승량에 따른 결과와 입력 조건을 검증합니다.
누적 상승 전처리는 별도 `ElevationCalculatorTests` 대상입니다.
이 테스트는 정책 구현의 일관성을 확인하며 실제 러너 체감·DEM 정확도 검증을 대신하지 않습니다.

변경 시에는 정책 버전, 경계값 테스트, 저장 프로필을 어떻게 갱신할지 함께 결정합니다.
